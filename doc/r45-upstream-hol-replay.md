## ARM MiniSat failure and signed-char repair

The old HOL4 tree builds MiniSat 1.14p as an external tautology helper.  On
this ARM host the initially built executable mishandles root-level units.  The
two-variable formula

```text
p cnf 2 3
1 2 0
-1 0
-2 0
```

is UNSAT, but the unmodified executable returned `SAT` with model `-1 -2`.
The input SHA-256 is
`e7b6755c091b5e0f9da1f97d1cb9ba99c69fadf8b91156df65da2492b8739d7a`
and the incorrect result SHA-256 is
`3a9529ad88b0687bfd151138ff73c65f6e4ac724c8b07ee5ef1904bc689ca271`.
As a control, the equivalent four-clause formula without unit clauses was
correctly reported UNSAT.

Calling the solver's simplifier after each parsed clause repairs the tiny
example but still returns invalid SAT models on larger CNFs generated by HOL4.
That patch is therefore not treated as a fix and is not part of any accepted
build.

The architecture-specific cause is now isolated.  AArch64 GCC defines
`__CHAR_UNSIGNED__`, while this MiniSat fork stores the lifted Boolean values
`-1`, `0`, and `1` in `vec<char> assigns`.  Reading stored false assignments
back as 255 corrupts the solver's three-valued comparisons.  Building the
exact committed source with `-fsigned-char`, without the experimental parser
change, made all 16 retained failing HOL-generated CNFs return exit 20 and
made the bundled resolution traversal end at the empty clause.

[`build_upstream_hol_minisat.py`](../tools/build_upstream_hol_minisat.py)
extracts source blobs from the pinned HOL4 commit rather than the possibly
dirty worktree, verifies that `-fsigned-char` clears `__CHAR_UNSIGNED__`, and
hash-binds the compiler, sources, build log, and output executable.
[`audit_upstream_hol_minisat.py`](../tools/audit_upstream_hol_minisat.py) then
checks the retained seven-variable regression CNF in two ways: MiniSat's own
resolution traversal must reach the empty clause, and `minisatProve.GEN_SAT`
must return a HOL4 kernel theorem without its internal-DPLL fallback warning.
The direct and HOL-invoked 95-byte proof traces are required to be identical.

### Sequential kernel-leaf runner and pilots

[`run_upstream_hol_gluing_batch.sh`](../scripts/run_upstream_hol_gluing_batch.sh)
now executes the same generated gluing script one pair at a time through
HOL4's `smlExecScripts.exec_script`.  It deliberately bypasses upstream
`run_script_pbl`'s 40-way queue setup while preserving the exact script text,
the signed MiniSat call, and the HOL kernel boundary.  On the retained d10
pilot, the old and new `Script.sml` files are byte-identical with SHA-256
`918a48bfc47279946198ba8cd191fd6a856c49d2f426941d696c6f74883ade61`.
The direct route reduced that same leaf from 669.39 user seconds / 40.65 wall
to 13.79 user seconds / 15.45 wall.

The runner also takes an explicit positive `MEMORY_MB` argument rather than
silently inheriting upstream's global 8,000 MB setting.  It passes that value
only to the child HOL buildheap, emits it as a unique build marker, and the
auditor requires the exact requested value and records it in the audit JSON.
This keeps the upstream configuration file untouched while making a
high-memory leaf's resource boundary part of the checked evidence.

[`audit_upstream_hol_gluing_theories.sh`](../scripts/audit_upstream_hol_gluing_theories.sh)
generates the standard `.ui`/`.uo` dependencies, loads every exported theorem
in a new HOL4 session, and then invokes the independent
[`audit_upstream_hol_gluing_theories.py`](../tools/audit_upstream_hol_gluing_theories.py)
auditor.  For every listed pair it requires the exact generated script, all
six nonempty script/theory/dependency artifacts, exact child-build success
markers without warning or fallback, and a freshly loaded theorem whose
conclusion is `F`, whose hypotheses contain both published `C4524` clique
conditions, and whose hypotheses do not contain `F`.  The audit also
hash-binds the config, runtime entry point, signed MiniSat binary, and runner
sources.

## Claim boundary

At this checkpoint we may claim a clean, pinned HOL4 runtime build and two
checked upstream theory stages.  We may not claim global enumeration
completeness, any degree-10 or degree-12 full gluing product, `R(4,5)=25`, or
`R(5,5) <= 45`.  Those statements remain contingent on the unfinished stages
above and their independently audited computational leaves.
